## 1. DE worldstate parser (pass 14 §1)

**Verdict: sound at its core; several quiet-degradation paths worth calling
out.**

- Fixture fidelity: `fixtures/worldstate.json` is a genuine DE payload —
  `$date`/`$numberLong` epoch-millis strings, integer `Time`, `Modifier`
  `VoidT1..T6`, `Hard` Steel Path flag, `PrimeVaultTraders`/`VoidTraders`
  nodes. The parser's schema assumptions match what DE actually sends.
- `de_date` (`src/model.rs:669`) and `de_str` (`src/model.rs:693`) both
  **risk**: a missing or renamed field degrades to an empty string
  (`""`) without appearing in any parity/gaps channel. Compare
  `decode_tier` (`src/model.rs:751`), which pushes unknown tiers into
  `gaps` — good — but the section-level parse sites do not. A renamed
  `ActiveMissions` would silently yield empty arrays and an empty plan,
  which the "no silent substitution" rule (addendum §rule, items 51–52)
  treats as unacceptable for *substituted* data; this is not substitution,
  but it is silent loss.
- **risk** — `de_date` failure feeds a fail-open guard: an unparseable or
  empty `Alert.activation` makes `corroborates_activation`
  (`src/elog.rs:328`, `Err(_) => return true` at `src/elog.rs:331`)
  return `true`, i.e. an alert with a *degraded* timestamp skips the
  activation guard entirely. The comment justifies empty (legacy feeds),
  but a DE-side timestamp format change would also land here rather than
  in `gaps`. Visible loss would be better.
- **risk** — `rank_fissures` (`src/plan.rs:448`): an unparseable/empty
  `expiry` silently drops the fissure from ranking (`parse_time(..)?`),
  and the remaining-live filter (`src/plan.rs:1534`) does the same. No gap
  or log entry. A dropped fissure looks like "DE has no fissures".
- **nit** — `faction` is rendered from the raw DE string; if DE renames a
  faction no gap is recorded (mission-side, tier mapping is guarded).
- **nit (accepted by design)** — fresh-HTTP-200 semantics are correct:
  `worldstate_status_label` (`src/model.rs:775`) labels a cache/fixture
  view STALE *even when the payload is fresh* (`fetched_live` gate,
  `src/model.rs:780–781` comment; tests at `src/model.rs:1978–1989`),
  and the cache is only written after a `Time`-bearing real payload check
  (`src/fetch.rs:130–135`). This matches the brief's stricter reading;
  verified `WORLDSTATE_STALE_AFTER_MINUTES = 10` (`src/model.rs:770`).

## 2. Quit fix (pass 14 §2 + pass 15 §1)

**Verdict: diagnosis correct and the test is genuinely D-Bus-level.**

- The original exit-hang was real: `do_report` ran inline in the loop, so
  Quit queued behind a wedged fetch. Pass 14 (ce3bf05) reordered teardown
  and finalized with `process::exit(0)`; pass 15 (63c4c78) moved reports
  onto spawned tasks (`schedule_report!` bounded at the call site,
  `src/resident.rs:393/404`) and bounds every teardown step: report- and
  capture-start aborts via `TASK_ABORT_TIMEOUT = 2s`
  (`src/resident.rs:50, 387–411`), capture join via
  `CAPTURE_JOIN_TIMEOUT = 2s` (`src/resident.rs:48, 416`),
  watch thread via `WATCH_JOIN_TIMEOUT = 2s` (`src/resident.rs:425`),
  tray shutdown via an explicit 3s timeout (`src/resident.rs:435`),
  `stop_capture`/`join_thread_bounded` at `src/resident.rs:789/802`.
  Unstoppable threads are detached and reaped by `process::exit` in
  `main` — every remaining await on the teardown path is bounded.
- `tests/tray_quit.rs` answers the brief's key question directly: it
  spawns the **real binary** (`target/debug/fracker`) under a private
  `dbus-daemon`, wedges outbound HTTP through a black-hole proxy injected
  via `HTTP_PROXY` (so the report fetch hangs for real, not mocked), and
  clicks the tray Quit item by sending a dbusmenu `Event` (`"clicked"`)
  over the real session bus — no test double on the menu side. It then
  asserts the process exits within 10s and emits `[teardown] complete`.
  A zombie (pre-fix behavior) fails this test. This is as close to "does
  the real binary exit" as a test can get.
- **risk (test portability)** — the gate hard-asserts `dbus-daemon` is on
  PATH (verified present here, `/usr/bin/dbus-daemon`) with no skip
  mechanism; environments without a dbus daemon will fail the suite
  rather than skip. Acceptable for a desktop-resident project, worth a
  comment.
- **nit (benign)** — a report-task panic would leave its
  `job_rx`/`job_tx` pair unfired; the loop continues and any later queued
  report request may see its trigger stuck as `queued` in the app log
  until the next tick. It cannot wedge the process.

## 3. Capture (passes 13–15) — PipeWire FFI and wait-for-node

**Verdict: structurally correct and well-instrumented, with one real
unsafe-code risk to fix.**

- Symbols: `REQUIRED_SYMBOLS` (`src/screencast.rs:752–773`) matches
  PipeWire 1.x headers (`pw_stream.h`, `pw_registry.h`, `spa/utils`,
  `stream/events.h` layout comments are in the file); dlopen-time
  verification at `src/screencast.rs:855` reports *which* symbol is
  missing. Registry listeners subscribe with version 3, stream events
  with version 2 — both match the 1.x struct sizes (tested,
  `src/screencast.rs:1854–1875`).
- **bug/risk** — `on_param_changed` reads a **fixed 256 bytes** from the
  SPA pod (`std::slice::from_raw_parts(param as *const u8, 256)`,
  `src/screencast.rs:1497`) regardless of the pod's actual size. Probe
  pods are near-always ≥256B on 1.x so this stays in-bounds in practice,
  but it is reading past the object when a smaller pod arrives; it
  should use the pod's size field (or `spa_pod_is_none`-style iteration)
  instead of a hand-rolled constant.
- **risk** — `ScreenCastSource::Drop` (`src/screencast.rs:1316`) calls
  `pw_stream_disconnect`/`pw_core_disconnect` without holding the
  thread-loop lock (the main loop's inline-connect callbacks cannot race
  here in the current wiring, but a future use case could). Also
  **risk**: `on_process` submits frames into an unbounded channel with
  the slowdown risk the code comment itself admits — frames continue if
  the consumer stalls.
- **nit** — `pw_registry_add_listener`'s int return at
  `src/screencast.rs:1115` is ignored (not even logged); an EPERM
  would look like "no nodes ever appear".
- Wait-for-node is right: bounded by `NODE_WAIT_TIMEOUT = 5s`
  (`src/screencast.rs:654, 1168–1180`), the registry dumps *all* Portal
  nodes at subscribe time (no flicker race for nodes registered before
  and after), and unknown-node ids are logged with their raw node id —
  the cause of a failed match is distinguishable on the next live run.
- Stage reporting is honest: `failure_stage(got_first)`
  (`src/screencast.rs:1255`) flips pre/post-first-frame, and
  `run_capture`'s progress only fires after a real frame
  (`src/capture.rs:505`), so the resident worker's stage mapping
  (`src/resident.rs:556–640`) cannot claim success before data exists.

## 4. Tab scoping (pass 15 §3)

**Verdict: airtight for the state the code keeps, modulo one safe-direction
click-origin race.**

- The token is per-regeneration: `next_generation()`
  (`src/report.rs:137`) = worldstate-independent nanosecond instant +
  atomic counter, monotonic across consecutive runs (tested:
  `consecutive_generations_stamp_different_tokens`,
  `src/report.rs:601`). This is exactly the fix 06731d6 makes — the
  first cut (7c29936) reused the report `now` and collided across
  regenerations from the same cached payload.
- Server/refresh path: every plan request re-reads the disk file and
  reads the token *from the file being served*
  (`body_generation`, `src/server.rs:287–309`), then `scope_to`
  (`src/server.rs:253, 298`) keeps the remembered tab on the 60s
  refreshes of one generation and clears it when the generation changes.
  The served page does carry the renderer's token (`inject_ticks`
  preserves body attributes — tested `inject_ticks_preserves_renderer_attributes`,
  `src/server.rs:475`).
- Legacy handling: a `plan-tab.json` without a generation is treated as
  unscoped (legacy `TabStore` test in `src/tabs.rs`) and older files
  clear correctly.
- **risk — click-origin race**: tab clicks (`record_tab`) are stamped
  with the generation the *server* currently has, not the generation the
  clicked tab was rendered to. A click in flight across a regeneration
  is attributed to the NEW generation and would be *cleared* by the
  next refresh rather than surviving (safe direction, but not strictly
  airtight against click origin). Not fixable without complex
  cookie-echo plumbing; document as a known limit.
- **nit** — `docs/demo-plan.html:81` carries the new token
  (`data-generation="1792469204421340757-0"`), consistent with the
  renderer (asset regen in 7c29936 + 06731d6).

## Overall verdict

Passes 14 and 15 did the hard work correctly. The DE parser's schema
assumptions hold against a real payload, its `Modifier`-tier and
freshness logic is right, and its gaps channel is the model the other
decoding sites should copy; the Quit fix correctly identified a loop
await in front of the report as the zombie, the pass-15 restructure
bounds **every** teardown step with timeout constants, and
`tests/tray_quit.rs` is the kind of integration test that would fail the
pre-fix zombie for real (private `dbus-daemon` + black-hole HTTP proxy +
genuine dbusmenu click on the spawned binary), though it hard-requires
dbus on PATH with no skip. Capture's FFI surface matches PipeWire 1.x
and the 5s wait-for-node will discriminate not-found causes, but
`on_param_changed`'s fixed 256-byte probe read (`src/screencast.rs:1497`)
is a genuine past-its-size unsafe dereference that should read the
pod's own size, and the unlocked Drop is worth a lock. The generation
token is per-run and distinguishes regen from refresh everywhere it is
actually compared, with only a benign (safe-direction) click-origination
race across regenerations. The weeklies audit met its own standard of
evidence on all three spot-checked vendors (Acrithis, Palladino, and the
Chipper removal) — an evidence bar most vendor audits never reach. No
regressions, no dormant worldstate path, and the single data-pack-rule
borderline (`decode_tier`'s tiny baked era map) is defensible. My grade:
**GO** with two concrete follow-ups on the next pass — fixes for the
pod-size read and (preferred) visible-loss reporting for unparseable
worldstate timestamps instead of fail-open corroboration and silently
dropped fissures, plus a guard that keeps golden timestamps tied to the
committed fixture.
